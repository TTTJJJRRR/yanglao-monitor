## 〇、先读这一段：为什么**不能**用假数据（很重要！）

你可能以为"采集数据 = 随便造点数字凑一下就行"。**这是最大的误会，必须先在脑子里转过来：**

我们这套系统最后要靠一个 AI 模型（CNN）来识别"老人在干嘛"——是走路、坐着、躺着、还是摔倒了。
模型**不是靠人告诉它规则**，而是靠**看大量真实的雷达信号**自己学会区别的。

- 如果你喂给它**假的/随机的数字**，它就学了个寂寞——到时候识别全错，等于白做。
- 之前我们已经踩过这个坑：用单一一类假数据训出来的模型，名义上"能跑"，实际上**认不出任何动作**。这就是为什么说"假数据没用"。
- **尤其是"摔倒"（falling）这一类**：全世界的公开数据集里几乎没有老人摔倒的毫米波数据，所以我们**必须自己采**。这一类比什么都重要，因为它关系到老人安全。

**一句话记住：我们要的是你拿真雷达、真人对着做动作，采出来的真实波形文件。不是 Excel 里编的数字。**

下面就是一步步怎么采。别怕，每一步都有"复制粘贴"的命令，照着敲就行。卡住了把报错截图发群里，滕哥或我来帮你。

## 一、你需要准备的东西（硬件）

| 物品 | 说明 |
|---|---|
| IWR6843AOP 雷达板 | 就是刚到货那块，天线已经封装在板子上，不用外接天线 |
| 5V 电源 / 或配套供电线 | 板子要单独供电才能稳定工作 |
| 一根 micro-USB 数据线 | 连电脑用，负责传数据 |
| 一台 Windows 电脑 | 装下面那些软件用 |
| 一个支架（或稳当的桌子） | 把雷达支到离地 **1.0～1.5 米** 高，朝向人的胸口位置 |
| 一块地垫（采"摔倒"时用） | 安全第一，见第六节 |

> 软件都装在**你的电脑**上，和雷达用 USB 连。

## 二、装软件（一次性，大概 30 分钟）

按下面顺序装，别跳。

### 2.1 装 Python（如果电脑还没有）
1. 打开浏览器搜 "Python 下载"，进 python.org，下 **Python 3.11 或更新版本** 的 Windows 安装包。
2. 双击安装，**务必勾选 "Add Python to PATH"**（最下面那个勾），然后点 Install。
3. 装完按 `Win+R` 输入 `cmd` 回车，黑框里输入：
   ```
   python --version
   ```
   如果显示一个版本号（比如 Python 3.11.x），说明装好了。

### 2.2 装两个 Python 库（采集脚本要用）
在刚才那个黑框（cmd）里输入：
```
pip install pyserial numpy
```
看到 "Successfully installed" 就 OK。（如果提示 pip 不是命令，重启一下 cmd 再试。）

### 2.3 装 TI 的 mmWave SDK（雷达的"驱动+示例程序"）
1. 去 TI 官网搜 **"mmWave SDK"**，下 3.6.x 版本（免费，要填个邮箱）。
2. 安装后，在安装的文件夹里找到一个关键文件（名字差不多这样）：
   ```
   xwr68xx_aop_mmw_demo.bin
   ```
   它一般在 `mmwave_sdk_xx/packages/ti/runtime/xwr68xx/mmw/` 这种路径下。
   这个文件就是雷达要跑的"出厂示例程序"，下一步要烧进板子。

### 2.4 装 UniFlash（用来把上面的 .bin 烧进雷达）
1. 去 TI 官网搜 **"UniFlash"** 下载安装（也是免费）。
2. 装好先放着，第三节用。

---

## 三、第一次：烧录固件（只做一次）

"烧录"就是把示例程序写进雷达板子里，让它知道怎么工作。

1. 用 micro-USB 把雷达连上电脑，**先不要供电**（或保持断电状态）。
2. 打开 UniFlash。
3. 在设备里选 **IWR6843AOP**（或选 "Connect to" 后识别到的型号）。
4. 找到 "Program" / "Browse" 按钮，选中第二节找到的 `xwr68xx_aop_mmw_demo.bin`。
5. 点 **Program / Load** 开始烧录，等进度条走完显示成功。
6. 给雷达**上电**（插 5V 电源）。现在雷达已经在跑示例程序了。

> 第一次可能会卡在"识别不到设备"，常见原因：USB 线没插紧、板子没先断电再连、驱动没装。卡住了截图发群。

---

## 四、确认电脑"看到"了雷达（找 COM 口）

1. 雷达上电、USB 连好后，在电脑上：
   - 右键"此电脑" → 管理 → 设备管理器 → 展开"端口 (COM 和 LPT)"
2. 你会看到**两个**名字像 `Silicon Labs` / `XDS110` / `USB Serial Port` 的口，比如：
   ```
   COM4  (XDS110 Class ... UART)
   COM5  (XDS110 Class ... UART)
   ```
   - 其中一个是 **CLI 口**（115200 波特），另一个是 **DATA 口**（921600 波特）。
   - **我们要的是 DATA 口**。一般两个里**数字大的那个**是 DATA 口（比如 COM5）。
   - 拿不准？两个都试一下就行——脚本连错口会立刻报错"打不开"或"没数据"，换另一个就行。

> 把这个口记下来，比如 **COM5**，下面要用。

---

## 五、跑采集脚本（核心步骤，每录一段都这样）

### 5.1 先到你项目的文件夹
打开 cmd，用 `cd` 进到项目根目录（就是放着 `edge/` 和 `data/` 的那个文件夹）。例如：
```
cd C:\Users\你的名字\...\大创-真正版本
```
> 不会找？在文件夹地址栏复制路径，cmd 里 `cd 粘贴的路径` 回车。

### 5.2 录一段的命令（复制粘贴，改两个地方）

下面是一条完整命令，**你只需改两处**：
- `--port COM5` → 改成你刚才记的口（比如 COM5）
- `--out .../A01/mmwave` → 改成"这次要采哪一类"

```bash
python edge/capture_oob.py --port COM5 --baud 921600 --out data/radar/E01/S01/A01/mmwave --seconds 30
```

**这条命令的意思**：连上 COM5 雷达，采 30 秒，把点云存到 `data/radar/E01/S01/A01/mmwave/` 文件夹里。

### 5.3 录的时候你做啥
1. 敲下回车，脚本会打印 `[采集] 打开 COM5 ...`，然后**开始录**。
2. **这 30 秒里，人就对着雷达做对应动作**（比如 A01 就是走来走去）。
3. 30 秒到，脚本打印 `[采集] 完成，共 NNN 帧` 就结束了。
4. 打开那个 `mmwave` 文件夹，应该看到一堆 `frame0000.bin`、`frame0001.bin`…… 这就是采到的真实数据！

### 5.4 第一次录完，先验证一下（很重要）
录完 A01 后，在 cmd 里跑这条（确认采到的真是有效数据，不是空的）：
```bash
python -c "from backend.app.inference.mmwave_cnn.preprocess import load_mmwave_frames; f=load_mmwave_frames('data/radar/E01/S01/A01/mmwave'); print('帧数', len(f), '首帧形状', f[0].shape if f else None)"
```
- 正常会显示 `帧数 几百~上千` 和 `首帧形状 (N, 3)`。
- 如果显示 `帧数 0` 或报错"解析不出点"：**别慌**，这是脚本和雷达版本对不齐的常见问题，把截图发群里，滕哥或我来调解析参数。绝对**不要**因为这个自己编数据凑数。

## 六、要采哪些动作（活动清单）

文件夹里的 **A 编号 = 动作标签**，你照着下表一类一类采。**每一类都要换不同的 `--out` 路径**。

| 编号 | 动作（人做什么） | 录的时候注意 |
|---|---|---|
| **A01** | 走动 walking | 在雷达前正常来回走 30 秒 |
| **A02** | 站立不动 standing | 站着别动 30 秒（可以稍微晃一下，更像真人） |
| **A03** | 静坐 sitting | 搬把椅子坐着 30 秒 |
| **A04** | 躺下/卧床 lying | 躺床上或垫子上 30 秒 |
| **A05** | 起身 standing_up | 从坐/躺**慢慢站起来**的动作，反复做满 30 秒 |
| **A06** | 弯腰/蹲下 crouching | 弯腰捡东西、或慢慢蹲下站起，反复 30 秒 |
| **A07** | **跌倒 falling（最重要）** | 见下面"安全规范"，**绝对不能真摔** |

> 路径例子：
> - A02 → `data/radar/E01/S01/A02/mmwave`
> - A07 → `data/radar/E01/S01/A07/mmwave`
> 以此类推，把命令里的 `A01` 改成对应的编号即可。

### 每类要采多少（达标线，别凑数）
- **每个人**每一类：**至少录 10 段**（每段 10～30 秒都行，建议统一 30 秒好管理）。
- **至少找 3 个不同的人**当受试者（S01、S02、S03……），尽量有高有矮、有胖有瘦。
- 文件夹结构长这样（**S 改成人编号，A 改成动作编号**）：
  ```
  data/radar/E01/S01/A01/mmwave/frame0000.bin ...
  data/radar/E01/S01/A02/mmwave/frame0000.bin ...
  data/radar/E01/S02/A01/mmwave/frame0000.bin ...
  ...
  ```
  标签就是文件夹名字里的 A 编号，**不需要你额外写标注文件**，系统自动认。

## 七、⚠️ "跌倒"类怎么安全采（必须看）

跌倒是项目里最关键的一类，但**绝对不能让人真摔**：
- 在**地垫**上做"模拟跌倒"动作集：慢慢跪下、侧身滑倒、扶墙慢慢下滑、快速蹲下。
- 旁边**必须有人保护**，动作**慢一点**，宁可多录几段"慢动作版"，也不要冒受伤风险。
- 受试者签个简易知情同意（校内大创项目，记一下年龄区间、体型区间即可，脱敏，不写真名）。

> 记住：我们宁可要"慢动作安全版"的跌倒数据，也不要任何人受伤。安全永远第一。

## 十、常见问题（卡住了看这里）

**Q1：脚本一跑就报错 "could not open port COM5"**
→ 口不对或雷达没上电。检查雷达是否供电、USB 是否插紧，回第四节换个 COM 口试。

**Q2：脚本能跑，但 30 秒后显示 `共 0 帧` / 验证命令 `帧数 0`**
→ 这是脚本解析和雷达版本对不齐，**正常现象，不是你错**。把 cmd 截图发群里，滕哥或我来改解析参数，你不用自己琢磨。

**Q3：设备管理器里找不到 COM 口**
→ 多半是 USB 驱动没装或线不对。换根线、换个 USB 口，或装一下 XDS110 驱动（TI 官网有）。

**Q4：python / pip 提示"不是内部或外部命令"**
→ Python 没加进 PATH。重装 Python 时勾选 "Add to PATH"，或重启 cmd。

**Q5：雷达连上但点云乱跳/没点**
→ 检查人是否在雷达正前方 1～3 米内、有没有大金属遮挡；支架高度是否在 1.0～1.5 米。
