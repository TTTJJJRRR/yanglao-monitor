## 1 项目背景（先对齐）

**项目**：基于毫米波雷达（型号 **IWR6843AOP**，60GHz 天线封装版 3T4R）+ 视频融合的**智慧康养主动预警系统**。

**用途**：监测独居 / 机构老人的跌倒、呼吸 / 心率、睡眠呼吸暂停、行为、情绪；出事秒级报警、叫到人；**不拍画面、不戴设备**（雷达不录视频，老人身上无需佩戴任何东西）。

**团队（5 人）**：

| 成员 | 角色 | 核心职责 |
|------|------|---------|
| 滕家瑞 | 指挥 + 代码 | 技术闸门、融合算法主导、统筹协调 |
| 黄敬城 | 副手 + 前端 / 测试 | M0 脚手架、前端大屏、质量验收 |
| 周震宇 | 数据采集 | 唯一接触真实雷达 / 视频原始数据 |
| 万砚佶 | 标注 | 标注规范、数据集质量 |
| 陈意豪 | 文档 / 对外 | 需求基线、文献综述、论文 / 答辩材料 |

**总文档**：所有规矩以 `docs/大创项目统筹需求文档.md`（v1.2）为准，**有问题先翻该文档，不要重复询问**。

```markdown
- 配置 profile：______（例：profile_2d_80m / profile_3d_people_counting；
                        不确定先写"待导师张东霖确认"，但 8 月底必须给结论）
- 距被测者距离：______（建议 1.0~2.0 米，先写计划值）
- 俯仰 / 水平角度：______（例：正对胸口高度，俯角 15°）
- 帧率：20 fps（固定，勿改）
- 环境光照：______（例：室内日光灯 / 暗光卧室）

## 二、视频
- 分辨率：______（建议 1920×1080）
- 帧率：______（建议 25 或 30 fps）
- 机位角度：______（例：斜 45° 俯视，覆盖床边 + 活动区）
- 光照条件：______（暗光 / 正常 / 有遮挡，各场景分开写）

## 三、★雷达到货 ETA（最重要，必须给确定日期）
- 预计发货 / 到货时间：______（年月日）
- 当前状态：______（已下单 / 等导师批 / 在途）
- 若 9 月仍不到货，替代方案：______（用模拟数据跑，但必须提前说明）
```

**② 雷达到货 ETA**：在群里单独 @ 滕家瑞，告知"雷达预计 X 月 X 日到"。这是整条时间线的硬前提——未到货前用模拟数据跑流程，但必须给出确定时间。

**交付格式**：
- 雷达数据按主文档 §6.1 的 JSON 结构（`timestamp_ms` / `device_id` / `breath_rate` / `heart_rate` …）。
- 视频动作标签固定 6 类：`walking, falling, sitting_still, standing_up, lying, normal_activity`；表情 6 类：`happy, sad, angry, anxious, calm, surprised`。
- **雷达与视频时间戳必须对齐（同一基准）**，否则后续融合无法进行。

**卡点求助**：配置 profile 不懂 → 问导师张东霖；JSON 结构不懂 → 问黄敬城（后端按此解析）。

### 3.2 万砚佶（标注）

你需在 M2 前把"怎么标"定下来。交付文件：`docs/标注规范v0.1.md`（复制下方模板填空）。

```markdown
# 标注规范 v0.1（万砚佶）

## 一、视频标注
- 场景分类：独居模拟 / 普通家庭 / 高密度场所
- 动作类别（6 类，不许改）：
  walking, falling, sitting_still, standing_up, lying, normal_activity
- 表情类别（6 类，不许改）：
  happy, sad, angry, anxious, calm, surprised
- 格式：COCO 风格 JSON，每条含 bbox（框）+ 动作类别 + 表情类别
- 示例一条：
  {"image_id": 1, "bbox": [x,y,w,h], "action": "falling", "emotion": "anxious"}

## 二、雷达标注（真值）
- 每段数据标：呼吸率参考值、心率参考值、是否呼吸暂停（是 / 否）
- 真值来源：______（例：对比医用指夹血氧 / 手动计数）

## 三、一致性要求
- 双人交叉标注，Kappa ≥ 0.8（低于 0.8 返工重标）
- 交叉标注搭档：______（写另一名标注人，M2 再定亦可）
```

**注意**：标签集已锁定（主文档 §6.2），**不得自创类别**，否则代码无法对接。标注质量决定模型上限。

**卡点求助**：标签含义不清 → 问滕家瑞；COCO 格式不懂 → 搜"COCO dataset annotation format"或问黄敬城。

## 6 常见问题（FAQ）

**Q：雷达没到，我（周震宇）现在能干什么？**
A：填写《采集参数清单》中可确定的部分 + 确认 ETA。模拟数据由黄 / 滕生成，不阻塞他人进度。

**Q：IWR6843AOP 与之前提的 IWR6843ISK 有何区别？**
A：AoP = 天线封装（Antenna-on-Package），板载天线，无需自行设计射频板，对学生团队更友好。型号已定，不再讨论。

**Q：标签集能加一个"跑步"吗？**
A：不能。6 动作 + 6 表情已锁定（主文档 §6.2），新增会导致代码无法对接。

**Q：Cursor 生成的东西要全信吗？**
A：不信。黄敬城验收、滕家瑞抽查。能跑起来 + 大屏有数据 = 过关，其余打回。

**Q：做不完怎么办？**
A：提前在周报写卡点，不要拖到 8 月底才说。早说明可调人协助。
