## 1 项目总览

| 项 | 内容 |
|----|------|
| 核心目标 | 毫米波雷达 + 视频双模态融合的**健康主动预警**系统 |
| 硬件 | TI IWR6843AOP 毫米波雷达（60GHz 天线封装版，3T4R）+ 低功耗高清摄像头 |
| 感知能力 | 呼吸频率、心率、睡眠呼吸暂停（AHI）、跌倒 / 行为识别、微表情 / 情绪 |
| 系统形态 | 边缘计算（家庭网关实时预处理 + 预警）+ 云端协同（存储 / 趋势 / 模型迭代） |
| 融合层级 | 特征级（降噪对齐）+ 决策级（CNN-LSTM / Transformer 跨模态关联） |
| 创新点 | “皱眉表情 + 心跳加速”联动判断焦虑；雷达隐私保护（不录制画面） |
| 关键指标 | 行为识别准确率 ≥95%、跌倒预警响应 ≤3 秒 |
| 预期成果 | 1 论文 + 1 专利 + 1 软件 + 1 数据集 + 研究报告 + 答辩 PPT |

**评审核心关注点**：评审最看重的是「融合算法创新、自有数据集、论文 / 专利」，而非“系统能否跑起来”。三个开源参考项目可加速脚手架，但无法替代这三件事。

## 3 协同与工具约定

### 3.1 三个智能体

| 智能体 | 身份 | 使用模型 | 职责 |
|--------|------|----------|------|
| WorkBuddy | 腾讯全场景 AI 工作台（战略统筹） | 深度思考模式 | 战略统筹、需求 / 架构文档、任务拆解、验收 Cursor 产物、跨模块一致性把关 |
| Cursor | 本地编码工具，经文件接力调用 | 最强编码模型（opus / gpt-5 类） | 所有重编码：后端、前端、WebSocket、Docker、算法骨架、DB Schema、单元测试 |
| 队友（人） | 4 名队员 | 不跑模型 | 交原始数据、做标注、写文档、跑测试 |

### 3.2 模型选型原则

- **A 类（推理 / 编码大模型）**：用于写代码、分析、统筹，可使用最强模型。
- **B 类（边缘端 AI 推理模型）**：部署在老人家里网关实时运行（如 YOLOv8n、MobileNet），必须轻量化，**不是越贵越好**。

### 3.3 文件接力流程

```
WorkBuddy ──写 tasks/xxx.md──→ 滕家瑞（Ctrl+L 粘贴给 Cursor）
                                   ↓
                              Cursor 最强模型执行
                                   ↓
                              写 results/xxx.* ←── WorkBuddy 读取验收
```

> 注：SDK 直连因本地环境不兼容而不可行，文件接力为当前稳定路径。委托脚本见 `cursor-orchestrator/relay.js`。

## 4 系统架构

```
┌─────────────────────────── 感知层（周震宇采集）──────────────────────────┐
│  TI IWR6843AOP 雷达(60GHz AoP 3T4R) ──UART/TLV──→ mmVital-Signs → 呼吸/心率/AHI │
│  高清摄像头 ──RTSP──→ 帧序列                                                │
└───────────────────────────────────┬──────────────────────────────────────┘
                                     │ 统一数据契约（见 §6）
┌─────────────────────────── 边缘 AI 层（网关）────────────────────────────┐
│  Fall-Detection 改造: YOLOv8(跌倒) + MediaPipe(姿态) + 行为/情绪分类       │
│  雷达生理信号分离(小波/自适应滤波) → 特征提取                              │
│  边缘预处理 + 紧急预警触发(响应 ≤3s)                                       │
└───────────────────────────────────┬──────────────────────────────────────┘
                                     │ WebSocket(实时) + HTTPS(批量)
┌─────────────────────────── 云端（滕+黄 主写，Cursor 编码）────────────────┐
│  FastAPI 后端 + PostgreSQL/SQLite + 模型迭代 + 长期趋势分析                 │
│  JWT 三角色(家属/管理员/老人) · WebSocket · Docker · CI/CD                  │
│  React 前端大屏(实时体征/行为/预警) + 告警推送(飞书/短信)                   │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                      融合算法层(核心创新, 自研)
          特征级对齐(雷达生理+图像局部特征) + 决策级(CNN-LSTM/Transformer)
```

**开源项目定位**（须在文档 / 答辩中如实说明来源与改造）：

| 层 | 开源参考 | 直接使用 | 必须改造的点 |
|----|----------|----------|--------------|
| 感知 | mmVital-Signs | 部分 | 缺 AHI 计算；需输出统一数据契约；当前雷达型号 IWR6843AOP |
| 边缘 AI | Multi-modal-Fall-Detection | 部分 | 缺“久坐 / 起身 / 久不动”行为标签；桌面端 → 边缘端部署改造 |
| 云端 / 前端 / 部署 | smart-greenhouse-iot | 脚手架 | 无多模态数据模型、无预警联动、无三角色权限 |

## 6 数据契约（交付规范）

> 队友必须按此结构交付，否则代码无法对接。契约由 WorkBuddy 定稿后交周 / 万作为模板。

### 6.1 周震宇（雷达 + 视频）交付规范

**雷达数据（统一 JSON 结构，Cursor 后端按此解析）**：

```json
{
  "timestamp_ms": 1690000000000,
  "device_id": "RADAR_01",
  "range_bin": 12,
  "breath_rate": 16.5,
  "heart_rate": 72.0,
  "chest_displacement_mm": 3.2,
  "motion_flag": false,
  "ahi_index": null
}
```

- 采集参数须记录：雷达型号、配置 profile、距被测者距离 / 角度、帧率（20fps）、环境光照。
- 视频：分辨率、帧率、机位角度、光照条件（暗光 / 正常 / 遮挡）。

**视频数据**：

- 场景分类：独居模拟 / 普通家庭 / 高密度场所。
- 动作标签集：`walking, falling, sitting_still, standing_up, lying, normal_activity`。
- 表情标签集：`happy, sad, angry, anxious, calm, surprised`（支撑 R-P2-01 情绪联动）。
- 必须与雷达时间轴对齐（同一时间戳基准）。

### 6.2 万砚佶（标注）交付规范

- 视频标注：COCO 格式 JSON，含 bbox + 动作类别 + 表情类别（高兴 / 悲伤 / 愤怒 / 焦虑 / 平静 / 惊讶）。
- 雷达标注：每段数据的生理信号真值标签（呼吸率 / 心率参考值、是否呼吸暂停）。
- 标注一致性：双人交叉标注，Kappa ≥ 0.8。

## 7 产品需求基线

> 本章为项目**单一需求基线**，由产品战略团队协作产出（用户研究 / 竞品 / 数据 / 需求 / 路线图五角色）。上游输入：三路调研 + 需求整合 + 时间线规划。已涵盖用户研究、竞品、SWOT、数据卡、15 项需求池、时间线与沟通要点。

### 7.1 执行摘要

**TL;DR**

- **核心定位**：以“非接触 + 隐私保护 + 多模态融合”的**消费级健康监护**切入居家 / 机构养老主动预警，前期暂避医械认证红海。
- **关键决策**：需求池共 15 项（P0×5 / P1×5 / P2×5），P0 安全刚需必须首发；核心创新（雷达 + 视频融合 / 情绪联动）锁定在 **M3 融合原型（10–11 月）** 集中兑现，作为评审命门优先保护。
- **数据支撑**：中度老龄化（60 岁 + 3.1 亿占 22%）+ 超 1.3 亿空巢独居 = 结构性刚需窗口；跌倒年约 4000 万次且为老人伤害致死首位（权威）；长护险 2028 全覆盖并将智能辅具纳入支付（最强支付侧利好）。

**核心结论卡片**

| 项目 | 内容 |
|------|------|
| 推荐方案 | 消费级“雷达生命体征 + 视频边缘骨骼化 + 多模态融合”健康监护，隐私双保险 + ≤3s 响应 |
| 优先级 | **P0 战略级**（居家安全刚需）+ P1 差异化 + P2 增值 |
| 预期影响 | 填补“全行业无人做雷达 × 视频 × 情绪真融合”的空白；契合国家适老化与长护险支付趋势 |
| 资源需求 | 现有 5 人团队 + Cursor 编码；M3 融合原型需滕家瑞亲自主导、早动手（9 月底设计启动） |
| 风险等级 | 中（雷达未到货、融合被质疑拼接、M4 数据集规模、已耗 5 个月）——均已有缓冲预案 |

### 7.2 产品目标

| # | 目标 | 正交性说明 | 关键成功指标（KPI） |
|---|------|------------|---------------------|
| G1 安全守护 | 以非接触、无感方式，对老人居家高危事件（跌倒、呼吸 / 心率异常）实时感知与秒级预警 | 管“出事能发现”（事件层） | 跌倒预警响应 ≤3s；行为识别准确率 ≥95%；生命体征连续可用率 ≥95% |
| G2 信息透明 | 为三类远程角色（子女 / 护理员 / 社区医生）提供分级、可追溯的状态与趋势可见性 | 管“远程看得见”（信息层） | 家属报警触达率 100%；医生月度趋势报告覆盖签约机构 |
| G3 技术差异化 | 以雷达 + 视频边缘融合（骨骼化）建立全行业空缺的“多模态 + 情绪联动”能力 | 管“别人做不到”（技术壁垒） | 融合覆盖率 100%（视频端侧骨骼化不原始上云）；情绪联动识别 M4 标定可用 |

> 正交性：G1 管事件安全、G2 管信息透明、G3 管技术壁垒，三者不重叠且互相支撑——G3 的融合能力是 G1 低误报与 G2 情绪关怀的技术底座。

### 7.3 用户故事

| 编号 | 角色 | 场景 | 映射痛点 |
|------|------|------|----------|
| US1 | 独居老人 | 夜间起身跌倒后系统自动检测并通知救援，无人看护时也能及时获救 | ① 跌倒无人知（事实） |
| US2 | 异地子女 | 每天收到父母状态日报（呼吸 / 心率趋势、是否跌倒、活动规律），远程了解健康而不频繁打扰 | ③ 黑箱焦虑（假设） |
| US3 | 机构护理员 | 一个看板同时看护多个床位，异常时收到优先级提醒与可追溯记录，少人覆盖多床、夜间不真空 | ⑤ 夜间真空（事实） |
| US4 | 社区医生 | 获得老人长期生命体征与跌倒风险趋势结论，据此做慢病 / OSA 随访决策 | 社区医生画像 |
| US5 | 家属 / 护理员 | 系统在“皱眉 + 心率异常”联动判定焦虑时主动提示，及时给予情感关怀 | 空白机会：情绪关怀 |

> 角色映射：系统权限为 JWT 三角色（家属 / 管理员 / 老人）。“护理员 / 管理者”→ 管理员角色；“社区医生”→ 经管理员授权后只读趋势数据的扩展角色，建议 M5 明确。

### 7.4 用户研究洞察

**四类用户画像**

| 画像 | 角色 | 核心诉求 | 敏感度性质 |
|------|------|----------|------------|
| 独居 / 居家老人 | 核心监测对象 | 无感、不穿戴、隐私 | 抗拒穿戴（假设）、隐私抵触（事实） |
| 异地子女家属 | 远程焦虑方 | 报警 + 安心感 | 信息黑箱焦虑（假设） |
| 机构护理员 / 管理者 | 运营方 | 少人覆盖多床、低误报、可追溯 | 怕误报、要可追溯（事实） |
| 社区医生 | 结论使用方 | 趋势结论做随访 | 要趋势不要原始数据（事实） |

**六大痛点（事实 vs 假设）**

| # | 痛点 | 性质 | 对需求影响 |

### 7.8 设计原则与非目标（Non-goals）

**设计原则**

- **消费级定位，暂避医械认证**：所有输出为健康趋势 / 风险筛查参考，不替代医生诊断；AHI、情绪一律定位“风险筛查 / 辅助提示”。
- **边缘骨骼化优先（隐私硬约束）**：视频仅在边缘网关提取骨骼 / 行为特征，原始视频与人脸绝不上云；合规可审计（R-P0-03 验收核心）。
- **BOM / 渠道双轨**：利用 TI IWR6843AOP 成熟生态压成本；优先切入政府适老化补贴目录 + 养老机构渠道，不硬刚 C 端价格战；家庭端借助补贴（厦门 50%–60%、杭州免费、南通最高 3000/户）压至千元内。
- **不依赖穿戴**：不要求老人佩戴任何设备即可完成核心监测。

**非目标（明确不做什么）**

- 不做医疗诊断 / 不宣称医械级（前期不申请 II 类医械认证）。
- 不原始视频上云（仅端侧骨骼化特征可上云）。
- 不正面 C 端价格战硬刚巨头（走补贴 + 机构侧切入）。
- 不对外宣称 ≥95% 准确率（M4 自建数据集实测验证前）。
- 不做全屋无死角 3D 重建（仅骨骼行为）。

### 7.9 待确认问题

1. **雷达型号已确认**：现行型号为 **TI IWR6843AOP**（60GHz 天线封装版，3T4R）。R60 廉价替代方案作为可选 BOM 备选，主型号已定，无需更换。

3. **医械认证路径**：前期消费级暂避，中长期是否规划 II 类医械证（对标清雷）？时间线与资源？
4. **补贴目录切入方式**：优先哪地（厦门 / 杭州 / 南通）？以“机构采购”还是“家庭补贴”为主入口？是否需先过适老化产品目录？

6. **数据合规边界（可选）**：骨骼化特征上云的合规口径、与长护险支付数据对接的合规要求。

```
            ├─→ 边缘网关(预处理) ─→ 视频端侧骨骼化(原始画面绝不上云)
视频(RTSP) ─┘                    ├─→ 单模态结果
                                 └─→ 融合引擎(特征级对齐+决策级联动) ─→ WebSocket/HTTPS ─→ 云端(存储/趋势/预警推送)
```

**三角色视图**：家属 App（报警 + 日报 + 趋势）、管理员 / 护理员看板（多床位优先级 + 可追溯）、老人端（无感，仅可选语音关怀）。

## 8 技术模块规格

### 8.1 后端 FastAPI `【交 Cursor 生成】`

- 数据接入：雷达 UART 解析服务 + 视频帧接收（RTSP / 文件）。
- 实时通道：WebSocket 推送体征 / 行为 / 预警。
- 存储：PostgreSQL（生产）/ SQLite（开发），含多模态数据表。
- 权限：JWT 三角色（家属 / 管理员 / 老人）。
- 预警引擎：规则 + 模型双重触发，响应 ≤3s（对应 R-P0-02）。

### 8.2 前端 React `【交 Cursor 生成】`

- 实时大屏：呼吸 / 心率曲线、行为状态、情绪、预警列表（对应 R-P0-04 / R-P1-03）。
- 技术栈参照 Greenhouse：Vite + TypeScript + Tailwind + Recharts。
- 响应式 + 暗色科技风。

### 8.3 融合算法 `【滕主导设计 + Cursor 骨架 + 自研训练】`

- 特征级：雷达生理特征（呼吸 / 心率 / 位移）与图像局部特征（微表情关键点）对齐降噪。
- 决策级：CNN-LSTM 或 Transformer 跨模态关联。
- 示例联动规则：`皱眉(图像) + 心率 > baseline*1.3(雷达)` → 焦虑预警（对应 R-P2-01）。
- 专利 / 论文核心，必须自有实现，不能抄开源。

### 8.4 边缘部署 `【交 Cursor 生成 + 滕适配】`

- 目标硬件：家庭网关（Jetson Nano / 树莓派 5 级）。
- 模型轻量化：YOLOv8n + 量化，脱离桌面 PyQt 形态。
- 边缘骨骼化管线（对应 R-P0-03）：原始视频绝不上云。
