## 3. 三智能体协同模型 + 模型选型

### 3.1 三个智能体分别是什么、跑什么模型

| 智能体 | 真实身份 | 用什么模型 | 负责什么 |
|--------|---------|-----------|---------|
| **WorkBuddy（我）** | 腾讯全场景 AI 工作台 | **Hy3 + 深度思考模式（按 Tab 开启）** | 战略统筹、需求/架构文档、任务拆解、验收 Cursor 产物、跨模块一致性把关、写所有"非重编码"内容（文档/论文框架/专利交底框架） |
| **Cursor（贵模型）** | 肆月本地破解版 Cursor，经文件接力调用 | **最强编码模型（claude-opus / gpt-5 / composer-2 类）** | 所有重编码：后端、前端、WebSocket、Docker、算法代码骨架、DB Schema、单元测试、跑通开源参考实现 |
| **队友（人）** | 4 名队员 | 不跑模型 | 交原始数据、做标注、写文档、跑测试 |

### 3.2 ⚠️ 一个必须澄清的"模型"歧义

肆月说"不差钱想用最适合的模型"。这里有两种完全不同的"模型"，别混：

- **A 类：聊天/推理大模型**（Hy3、Cursor 里的 opus/gpt-5）—— 用来**写代码、做分析、统筹**。
  这类肆月想用多强用多强，没问题。
- **B 类：边缘端 AI 推理模型**（YOLOv8n、量化后的 CNN-LSTM）—— 这是**部署在老人家里网关上实时跑的**，
  要小、要快、不能上云端大模型。这类必须选轻量模型（如 YOLOv8n、MobileNet），**不是越贵越好**。

**结论**：A 类肆月随意上最强；B 类必须轻量化，这是工程常识不是省钱问题。

## 4. 系统架构（分层 + 开源参考映射）

```
┌─────────────────────────── 感知层（周震宇采集）──────────────────────────┐
│  TI IWR6843ISK 雷达 ──UART/TLV──→ mmVital-Signs(Python API) → 呼吸/心率/AHI │
│  高清摄像头 ──RTSP──→ 帧序列                                                │
└───────────────────────────────────┬──────────────────────────────────────┘
                                     │ 统一数据契约(见 §6)
┌─────────────────────────── 边缘AI层（部署在网关）─────────────────────────┐
│  Fall-Detection 改造: YOLOv8(跌倒) + MediaPipe(姿态) + 行为/情绪分类       │
│  雷达生理信号分离(小波/自适应滤波) → 特征提取                              │
│  边缘预处理 + 紧急预警触发(响应 ≤3s)                                       │
└───────────────────────────────────┬──────────────────────────────────────┘
                                     │ WebSocket(实时) + HTTPS(批量)
┌─────────────────────────── 云端（滕+黄 主写，Cursor 编码）────────────────┐
│  FastAPI 后端 + PostgreSQL/SQLite + 模型迭代 + 长期趋势分析                 │
│  ┌─ 参考 smart-greenhouse-iot-dashboard 架构 ─┐                            │
│  │  JWT 双角色(家属/管理员/老人) · WebSocket · Docker · CI/CD              │
│  └────────────────────────────────────────────┘                            │
│  React 前端大屏(实时体征/行为/预警) + 告警推送(飞书/短信)                   │
└──────────────────────────────────────────────────────────────────────────┘
                                     │
                          融合算法层(核心创新, 自研)
              特征级对齐(雷达生理+图像局部特征) + 决策级(CNN-LSTM/Transformer)
```

**开源项目真实定位**（务必在文档/答辩中如实说明来源与改造）：

| 层 | 开源参考 | 直接用？ | 必须改造的点 |
|----|---------|---------|------------|
| 感知 | mmVital-Signs | 部分 | 缺 AHI 计算；需输出统一数据契约；仅单人 |
| 边缘AI | Multi-modal-Fall-Detection | 部分 | 缺"久坐/起身/久不动"行为标签；桌面端→边缘端部署改造 |

## 6. 数据契约（队友必须按此交付，否则代码无法对接）

### 6.1 周震宇（雷达+视频）交付规范

**雷达数据（统一结构，Cursor 后端按此解析）：**
```json
{
  "timestamp_ms": 1690000000000,
  "device_id": "RADAR_01",
  "range_bin": 12,
  "breath_rate": 16.5,
  "heart_rate": 72.0,
  "chest_displacement_mm": 3.2,
  "motion_flag": false,
  "ahi_index": null
}
```
- 采集参数必须记录：雷达型号、配置 profile、距被测者距离/角度、帧率(20fps)、环境光照
- 视频：分辨率、帧率、机位角度、光照条件（暗光/正常/遮挡）

**视频数据：**
- 场景分类：独居模拟 / 普通家庭 / 高密度场所
- 动作标签集：`walking, falling, sitting_still, standing_up, lying, normal_activity`
- 必须**与雷达时间轴对齐**（同一时间戳基准）

### 6.2 万砚佶（标注）交付规范

- 视频标注：COCO 格式 JSON，含 bbox + 动作类别 + 表情类别(高兴/悲伤/愤怒/焦虑/平静/惊讶)
- 雷达标注：每段数据的生理信号真值标签（呼吸率/心率参考值、是否呼吸暂停）
- 标注一致性要求：双人交叉标注，Kappa ≥ 0.8

> 以上契约由我定稿后，交给周/万作为"交付模板"，他们照填即可，降低沟通成本。

## 7. 各模块需求规格（高层，标注编码归属）

### 7.1 后端 FastAPI `【交 Cursor 最强模型生成】`
- 数据接入：雷达 UART 解析服务 + 视频帧接收（RTSP/文件）
- 实时通道：WebSocket 推送体征/行为/预警
- 存储：PostgreSQL（生产）/ SQLite（开发），含多模态数据表
- 权限：JWT 三角色（家属 / 管理员 / 老人）
- 预警引擎：规则 + 模型双重触发，响应 ≤3s

### 7.2 前端 React `【交 Cursor 最强模型生成】`
- 实时大屏：呼吸/心率曲线、行为状态、情绪、预警列表
- 技术栈参照 Greenhouse：Vite + TypeScript + Tailwind + Recharts
- 响应式 + 暗色科技风（已验证 Cursor 能高质量产出，见 test-001）

### 7.3 融合算法 `【滕主导设计 + Cursor 骨架 + 自研训练】`
- 特征级：雷达生理特征(呼吸/心率/位移) 与图像局部特征(微表情关键点) 对齐降噪
- 决策级：CNN-LSTM 或 Transformer 跨模态关联
- **示例联动规则**：`皱眉(图像) + 心率> baseline*1.3(雷达)` → 焦虑预警
- 这是专利/论文核心，必须自有实现，不能抄开源

### 7.4 边缘部署 `【交 Cursor 生成 + 滕适配】`
- 目标硬件：家庭网关（Jetson Nano / 树莓派 5 级）
- 模型轻量化：YOLOv8n + 量化，脱离桌面 PyQt 形态
