# 人员分工与数据交付规范（详细版）

> 项目：基于毫米波雷达与视频图像融合的智能康养监测系统研发（江南大学 重点项目）
> 编写：WorkBuddy · 2026-08-05
> 用途：发给每一个队友，照着做、照着交。看不懂的地方直接问滕家瑞。
> 配套文档：`大创项目统筹需求文档.md`（架构与流程总览）

---

## 总原则（所有人先读这一段）

1. **代码统一进 GitHub 私有仓，禁止微信传文件当交付。** 分支策略见 §0。
2. **所有"数据"必须按本文规定的格式交**，否则滕家瑞那边代码接不上，等于白做。
3. **交东西前先自查**：文件命名对不对、字段齐不齐、例子能不能跑。
4. **每周日 22:00 前**在群里发一句进度（做了啥 / 卡在哪 / 下周计划）。
5. 看不懂任务？直接问滕家瑞，**别自己猜着做**——做错比不做更耽误时间。

## §0 代码仓库与分支规范（滕家瑞定，所有人遵守）

```
仓库：yanglao-monitor（GitHub 私有）
分支：
  main          ← 只有滕家瑞能合，稳定版
  dev           ← 日常开发主分支
  feat/backend  ← 滕/黄：后端
  feat/frontend ← 滕/黄：前端
  data/radar    ← 周震宇：雷达+视频数据
  data/label    ← 万砚佶：标注数据

提交流程：每个人从 dev 拉自己的 feature 分支 → 写完提 PR → 滕家瑞 review 后合入
禁止：直接推 main、把大文件（视频/数据集）塞进 git（用 Git LFS 或网盘链接）
```

## §3 周震宇（雷达 + 视频 数据采集）

> ⚠️ 你是**唯一能产出原始数据的人**，雷达不在滕手上，所以感知层能不能动全看你的进度。
> 数据必须严格按下面格式交，否则滕的代码解析不了。

### 角色定位
硬件与数据采集负责人。搭雷达+摄像头实验平台，采多场景数据，交原始数据 + 采集参数。

### 你要干的（按阶段）

| 阶段 | 具体任务 |
|------|---------|
| M0 | 确认雷达到手时间；先交一份《采集参数清单》（见下） |
| M1 | 搭 IWR6843ISK + 摄像头联调平台；用 mmVital-Signs 跑通呼吸/心率；**先交模拟/可用数据让滕跑通流程** |
| M2 | 真采多场景数据：独居模拟（跌倒/久不动）、普通家庭、高密度场所 |
| M4 | 持续补数据、保证数据集规模；记录环境参数 |
| M5 | 配合滕在真实场景（养老机构/社区）试点采集 |

### 你要交的数据 —— 【雷达数据格式】

每个采样点一条记录，存 JSONL（每行一个 JSON）或 CSV，字段**必须**如下：

```json
{
  "timestamp_ms": 1690000000000,
  "device_id": "RADAR_01",
  "subject_id": "P001",
  "range_bin": 12,
  "breath_rate": 16.5,
  "heart_rate": 72.0,
  "chest_displacement_mm": 3.2,
  "motion_flag": false,
  "ahi_index": null,
  "scene": "living_room",
  "env_light": "normal",
  "note": ""
}
```

| 字段 | 类型 | 说明 | 是否必填 |
|------|------|------|:---:|
| timestamp_ms | int | 毫秒时间戳（UTC），全系统统一时间基准 | ✅ |
| device_id | str | 雷达编号 | ✅ |
| subject_id | str | 被测者编号（P001/P002…） | ✅ |
| range_bin | int | 信号最强距离门 | ✅ |
| breath_rate | float | 呼吸频率（次/分） | ✅ |
| heart_rate | float | 心率（次/分） | ✅ |
| chest_displacement_mm | float | 胸腔位移（毫米） | ✅ |
| motion_flag | bool | 是否有大幅运动 | ✅ |
| ahi_index | float/null | 睡眠呼吸暂停指数（仅睡眠场景填） | 睡眠场景必填 |
| scene | str | 场景：living_room / bedroom / corridor | ✅ |
| env_light | str | normal / dark / occluded | ✅ |
| note | str | 备注（如"被测者穿厚睡衣"） | 可选 |

**采集参数清单（M0 就要交）：**
- 雷达型号、配置 profile 文件名、距被测者距离/角度、帧率(默认20fps)
- 摄像头型号、分辨率、帧率、机位角度、是否红外
- 每次采集的环境记录：光照、是否遮挡、被测者衣着/体型

### 你要交的数据 —— 【视频数据格式】

- 原始视频按场景分文件夹：`data/radar/videos/living_room/P001_001.mp4`
- 文件名规则：`{subject_id}_{序号}.{ext}`
- **必须与雷达时间轴对齐**：视频文件名 + 起始 timestamp_ms 写在一个 `meta.json` 里
- 视频分辨率/帧率记录在 meta.json

### 验收标准
- 滕能用你的 JSON 直接跑通后端解析，不报错
- 视频和雷达时间戳能对上（误差 < 200ms）
- 场景覆盖申报书要求的三类，且每个场景样本量达标（具体数量 M4 时定）

## §4 万砚佶（数据标注 + 文档协助）

> 标注质量直接决定模型上限。你交的标注格式不对，周的视频就白采。

### 角色定位
数据标注负责人 + 文档协助（论文/专利初稿主力）。把周采的视频和雷达数据打成可训练标签。

### 你要干的（按阶段）

| 阶段 | 具体任务 |
|------|---------|
| M2 | 基于滕给的标签集，起草《标注规范 v0.1》 |
| M3-M4 | **标注视频**：动作 + 表情；**标注雷达**：生理信号真值 |
| M4 | 双人交叉标注，算一致性(Kappa)；出标注报告 |
| M6 | 写论文初稿（多模态融合应用方向）、专利交底书初稿 |

### 你要交的数据 —— 【视频标注格式】

COCO 风格 JSON，每个视频一个标注文件：

```json
{
  "video_id": "P001_001",
  "fps": 30,
  "frames": [
    {
      "frame_id": 120,
      "timestamp_ms": 1690000036000,
      "boxes": [
        {"bbox": [x, y, w, h], "action": "falling", "emotion": "anxious"}
      ]
    }
  ]
}
```

**动作标签集（固定，不能自己加）：**
```
walking       行走
falling       跌倒
sitting_still 久坐/静止
standing_up   起身
lying         平躺
normal_activity 日常活动
```

**表情标签集（固定）：**
```
happy 高兴 | sad 悲伤 | angry 愤怒 | anxious 焦虑 | calm 平静 | surprised 惊讶
```

### 你要交的数据 —— 【雷达标注格式】

每段连续数据给一个真值标签文件：
```json
{
  "segment_id": "P001_seg_003",
  "breath_rate_ref": 16.0,
  "heart_rate_ref": 71.0,
  "apnea": false,
  "label_source": "device_readout / manual"
}
```
- `label_source` 写清楚真值是设备读出还是人工标定
- 呼吸暂停段必须单独标 `apnea: true` 并给持续时间

### 验收标准
- 标注文件能被滕的脚本直接加载，字段不缺
- 双人交叉标注 Kappa ≥ 0.8（低于此要返工）
- 论文/专利初稿在 M6 前提交给滕做技术校对
